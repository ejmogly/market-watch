## 환경 (클라우드 예약 실행)
- 당신은 Anthropic 클라우드에서 혼자 실행됩니다. 로컬 파일, 이전 대화, 다른 담당의 결과 파일은 없습니다. 이 프롬프트가 규칙의 전부입니다.
- Notion 기록 방법은 아래 순서로 고릅니다.
  1. **Notion 커넥터 도구**(이름에 `notion`이 들어간 MCP 도구)가 보이면 그것으로 DB를 조회·생성·수정합니다.
  2. 커넥터가 없거나 실패하면 **공식 REST API**를 씁니다. 인증은 (A) 환경의 API 자격 증명(`api.notion.com` 요청에 프록시가 헤더를 자동으로 붙임, 헤더 없이 요청) 또는 (B) 환경 변수 `NOTION_TOKEN`(`Authorization: Bearer $NOTION_TOKEN`) 중 설정된 쪽입니다. 토큰 값을 출력·기록하지 마십시오.
  - 공통 헤더: `Notion-Version: 2022-06-28`, `Content-Type: application/json`
  - DB `주식 데이터` database id: `<NOTION_ID>` · data source `collection://<NOTION_ID>`
  - 행 조회: `POST https://api.notion.com/v1/databases/<NOTION_ID>/query` · 행 생성: `POST https://api.notion.com/v1/pages` · 속성 수정: `PATCH https://api.notion.com/v1/pages/{page_id}` · 본문 추가: `PATCH https://api.notion.com/v1/blocks/{page_id}/children` (한 번에 블록 100개 이하)
  - 먼저 DB를 조회해 속성 이름·타입을 확인하고 시작합니다. 커넥터와 API가 모두 실패(401/403/404)하면 **아무것도 쓰지 말고** 멈춰서 "Notion 연결 또는 공유 설정 확인 필요"라고 보고합니다. 어느 방법으로 썼는지 마지막 보고에 적습니다.
- **여러 행 읽기는 view 모드만 씁니다**(한도 없음). `notion-query-data-sources`의 SQL 모드와 rows 모드는 워크스페이스 사용 한도에 걸리므로 쓰지 않습니다. 호출 형식: `{"data": {"mode": "view", "view_url": "<아래 URL>", "page_size": 100}}`. 필터가 더 필요하면 받은 뒤 python3로 거릅니다.
  - 검증 대기: `https://app.notion.com/p/<NOTION_ID>?v=<NOTION_ID>`
  - 최신(종목별 1행): `https://app.notion.com/p/<NOTION_ID>?v=<NOTION_ID>`
  - 전체, 기준일 최근순: `https://app.notion.com/p/<NOTION_ID>?v=<NOTION_ID>`
  - view 모드도 실패하면 `notion-search`(data_source_url 지정)로 찾고 `notion-fetch`로 읽습니다. 이름이 `[루틴]`으로 시작하는 view는 고치거나 지우지 않습니다.
- 계산은 `python3` 표준 라이브러리(`urllib`, `json`, `statistics`)만 씁니다. 패키지 설치 금지. 요청에는 브라우저 User-Agent를 넣고 요청 사이에 1초 이상 간격을 둡니다.
- **알림 금지**: PushNotification 같은 휴대폰·앱 알림 도구는 쓰지 않습니다(설정에서도 막혀 있음). 결과는 Notion과 마지막 보고에만 남깁니다.
- **이메일**: 외부 요청에 연락처 이메일이 필요하면(SEC EDGAR User-Agent 등) `<CONTACT_EMAIL>`만 씁니다. 허용되지 않은 도메인 주소는 절대 쓰지 않고, 이메일 주소를 지어내지 않습니다.
- 한국 시간(KST) 기준으로 날짜를 적습니다. 시작할 때 `date -u`로 현재 시각을 확인합니다. 마지막 보고는 **한국어**로 합니다.

## 값 규칙 (실습 2 이슈 기록에서 온 것 — 반복 금지)
- **기준일** = `basic.localTradedAt`의 날짜. 수집 날짜와 섞지 않습니다. 휴장일이면 기준일이 이전 거래일이므로 새 행을 만들지 않습니다.
- 가격·거래량은 `basic`과 `totalInfos`만 씁니다. `dealTrendInfos`는 외국인 보유율 대조에만 씁니다.
- 외국인 소진율은 전 거래일 값일 수 있습니다. 일별 동향표 보유율과 대조해 실제 날짜를 `외국인 소진율 기준일`에 적고 `비고`에 "외국인 소진율은 YYYY-MM-DD 값"이라고 씁니다.
- PER·EPS·PBR·BPS는 `실적 기준`(예: `2026.06.`)을, 배당은 `배당 기준`을 채웁니다. 배당이 N/A면 칸을 비우고 비고에 "네이버 증권 표기 N/A"라고만 씁니다(무배당이라고 해석하지 않습니다).
- **52주 최고·최저와 52주 범위 내 위치**는 네이버 표기값(`integration`)으로만 계산합니다. 일별 시세의 1년 최고·최저를 쓰지 않습니다.
- **이동평균(20·50·60·120·200일)과 14일 ATR**은 일별 시세 API 값만으로 계산합니다(`basic` 값과 섞지 않음). 이동평균 = 기준일로 끝나는 N거래일 종가의 단순 평균. ATR = True Range(고가−저가, |고가−전일 종가|, |저가−전일 종가| 중 최댓값)의 **와일더 평활**(첫 값 14개 단순 평균, 이후 (전 ATR × 13 + TR) ÷ 14). `일별 종가 범위`에 첫 날~기준일(거래일 수)을 적습니다.
- 투자의견 평균은 숫자 그대로("투자의견 평균 4.00"). "매수", "5점 만점", "매수·중립·매도를 점수화" 같은 풀이를 본문·**용어 풀이 표** 어디에도 붙이지 않습니다. 용어 풀이는 `네이버 증권이 표기한 증권사 투자의견의 평균값(숫자만 표기)`으로 씁니다.
- 외국인 소진율 표기 템플릿: `46.55%(2026-09-22 값) · 2026-09-23 외국인 보유율 46.63%` — 소진율 값에는 그 값의 실제 날짜를, 보유율에는 기준일을 붙입니다. 날짜와 값을 섞지 않습니다.
- 뉴스: 제목에 종목명이 든 기사를 먼저 고릅니다. 기사 날짜는 API의 게재 시각이고, 게재 시각이 **기준일 7일 전 00:00부터 수집 시각 사이**인 기사만 씁니다. 기준일 뒤에 나온 기사는 문장에 날짜를 적어 구분합니다. 제목은 API `title`에서 HTML 엔티티만 원래 문자로 바꿔(`html.unescape`) 그대로 씁니다. "..."로 끝나면 잘린 그대로 두고 추측해 채우지 않습니다. 기사 URL은 `출처` 목록에 넣습니다. 기사 속 숫자(목표주가 등)를 DB 값처럼 쓰지 않습니다.
- **뉴스 옮겨 적기**(2026-10-04 추가, 이슈 #26): 뉴스는 **그 종목 코드의** 뉴스 API에서만 고릅니다(다른 종목 API에서 찾은 기사를 쓰지 않음). python3로 고른 기사의 `datetime`·`officeName`·`title`(`html.unescape` 후)·URL(`https://n.news.naver.com/mnews/article/{officeId}/{articleId}`)을 한 줄씩 출력하고, 본문의 날짜·언론사·제목과 `출처` 칸에는 **그 출력을 그대로 붙여 넣습니다**. 제목을 기억이나 요약으로 다시 타이핑하지 않습니다(오타·뜻 바꾸기·지어낸 기사가 실제로 나왔음). 한두 줄 요약만 직접 씁니다.
- **전일 종가**(2026-09-26 Team 검토): 본문의 전일 종가·전일 대비는 네이버 `basic`·`totalInfos`의 '전일' 표기값입니다. '앞 거래일(YYYY-MM-DD) 종가'라고 쓰지 않습니다(일별 시세 종가와 4종목 모두 달랐음). 지표 표의 기준 시점은 `기준일 네이버 전일 표기값`으로 적습니다. 14일 ATR에 쓰는 전일 종가는 일별 시세 값이며 둘을 섞지 않습니다. 거래량은 본문에 쓰지 않습니다.
- 외국인 소진율과 일별 동향 보유율이 일치하는 날짜가 없으면 `외국인 소진율 기준일`을 비우고 비고에 `외국인 소진율 기준일 확인 불가(일별 동향과 불일치)`라고 씁니다. 날짜를 추측하지 않습니다.
- 컨센서스 `createDate`가 기준일과 다르면 `컨센서스 기준일`에 그대로 적고 비고에 `컨센서스는 YYYY-MM-DD 값`이라고 씁니다.
- 출처가 준 표기만 씁니다. 휴장 사유는 출처가 없으면 쓰지 않고, 정의·기준은 출처 표기(`2026.06.` 등)만 씁니다('최근 4분기'처럼 풀어 쓰지 않음).
- **자기 검산**: 현재가 = 전일 + 전일 대비인지 확인합니다. 일별 시세 API의 마지막 날짜·종가가 기준일·현재가와 다르면(장 마감 직후에는 당일 봉이 아직 확정되지 않았을 수 있음) 이동평균·ATR·한 줄 판단·구간을 비우고, 비고에 `일별 시세 미갱신(마지막 YYYY-MM-DD)`이라고 씁니다. 추정해서 채우지 않습니다.

## DB 행 규칙
- **종목명**(title) = `종목명-YYYY-MM-DD`(기준일). 예: `삼성전자-2026-09-25`
- **같은 종목코드 + 같은 기준일** 행이 있으면 새로 만들지 않고 그 행을 갱신합니다.
- 새 행은 `최신`을 체크하고, 같은 종목코드의 다른 행 중 `최신`이 체크된 것은 해제합니다.
- `검증` = `대기`, `실행 방식` = `예약`. `검증`·`검증 메모`는 검증 담당만 씁니다.
- `수집시각` = 수집한 KST 시각(datetime). `출처` = 번호 매긴 목록(이름 + URL + 조회 시각).
- 기존 컬럼은 모두 채웁니다(값이 없으면 비우고 비고에 이유). 추가 컬럼: `50일 이동평균(원)`, `200일 이동평균(원)`, `한 줄 판단`, `판단 근거`(한 줄 판단의 근거 숫자 한두 줄).

## 행 본문 (이 순서 그대로)
1. 요약 3문장 — 한 문장에 정보 하나
2. 지표 표 — 지표 | 값 | 쉽게 말하면 | 태그. 모든 지표 행에 기준 시점(실적 기준, 외국인 소진율 날짜 등)
3. 뉴스 2~3개 — 날짜 · 언론사 · 제목 · 한두 줄 요약 (보도)
4. 그래서 어떻게 볼까 — 아래 판단 규칙
5. 용어 풀이 — 표(용어 | 뜻). 행 본문은 본문 괄호 풀이 대신 이 표로 풉니다. 태그가 붙은 문장에 나온 용어는 어느 절이든 전부 표에 있어야 합니다.
6. 고지 문구(고정): `참고용 시나리오이며 투자 판단과 책임은 본인에게 있습니다.`
문체는 평서문 한다체. 이모지 금지. 큰 숫자는 읽히는 단위(시가총액 `1,674조 9,588억 원`).

## 문장 규칙 (실습 2 이슈 #11·#12·#14·#16·#17)
- 지표 하나에 문장 하나. "종가는 X원이다" / "전날보다 Y원 올랐다"는 두 문장입니다.
- 계산 문장에는 원 단위 출처 값을 넣지 않습니다("종가는 52주 최고가보다 24.6% 낮다").
- N/A 종목이 있으면 순위 범위를 밝힙니다("표기된 세 종목 가운데").
- 나눗셈 결과는 '배·비율'이라 하고 '차이'라 하지 않습니다. '훨씬·높은 편' 대신 숫자를 씁니다.
- '모두·전부' 뒤에 예외를 붙이지 않습니다.

## 태그 (문장 끝 회색 글씨)
(확인) 네이버 증권 표기값 그대로(단위 바꿈 포함) · (산출) 아래 DB 칸의 값을 그대로 옮길 때만: `20·50·60·120·200일 이동평균(원)`, `14일 ATR(원)`, `52주 범위 내 위치(%)`, `외국인 소진율 기준일` · (계산) 본문에서 새로 비교·순위·배수·% · (보도) 기사 인용 · (의견) 판단 문장에만.
- 종가와 이동평균의 비교("200일선 위에 있다"), 구간 경계를 반올림한 값은 (계산)입니다. 한 문장에 정보 하나(종가 / 전일 대비 / 등락률은 각각 다른 문장).
- 값 문장과 비교·순위 문장을 나눕니다("PER 8.31배다 (확인)" / "네 종목 중 가장 낮다 (계산)").
- "그래서 어떻게 볼까" 안에서도 사실 문장에는 (확인)/(산출)/(계산), 판단 문장에만 (의견).
- (의견) 문장은 값과 비교를 나누지 않습니다. 숫자가 괄호 출처로 추적되기만 하면 됩니다. 구간 하나 또는 조건 하나와 그 괄호 출처는 정보 하나로 봅니다.

## 판단 규칙 — 그래서 어떻게 볼까 (3~12개월 중기, 해외 종목과 같은 식)
- 형식(이 순서): 첫 문장 `아래 판단은 3~12개월 중기 관점의 시나리오다. (의견)` → 한 줄 판단 문장 → `과거 참고` 줄(아래) → 근거 3가지(번호 목록, 사실 문장, 태그는 (확인)/(산출)/(계산)/(보도), 가격 위치 1개 이상·가치/컨센서스 1개 이상) → 분할 매수 검토 구간 → 차익 실현 검토 구간 → 생각을 바꿀 조건.
- 비중 축소는 분할 매수 구간이 없으므로 손절 숫자도 없습니다(의도된 것, 해외 종목과 같음). 생각을 바꿀 조건에는 올릴 조건 한 줄만 씁니다.
- 한 줄 판단: 관심 = 종가 ≥ 200일선 그리고 50일선 ≥ 200일선 · 비중 축소 = 종가 < 200일선 그리고 50일선 < 200일선 · 나머지 관망.
- 분할 매수 검토 구간: 관심 = 20일선 ~ 50일선(낮은 값~높은 값) · 관망 = "종가가 200일선 위로 마감하면" 200일선 ~ 200일선 + 1 ATR · 비중 축소 = "신규 매수 검토 안 함".
- 차익 실현 검토 구간: 하단 = min(52주 최고, 목표가 평균), 상단 = max(둘). 목표가 평균이 종가보다 50% 넘게 높으면 "목표가 편차가 커서 하단만 참고".
- 손절 기준(생각을 바꿀 조건): 분할 매수 구간 하단의 **반올림 전 값** − 2 × ATR, 결과를 마지막에 한 번만 내림. 관망은 조건부 구간 하단 기준. 비중 축소는 "200일선 위로 두 번 연속 마감하면 관망으로 올림".
- 확인 방식은 종가 기준("종가가 … 마감하면").
- 간격 검산: 손절 줄 괄호에 `(A − L) ÷ 와일더 14일 ATR = x.x배`를 적습니다(A = 매수 구간 하단, L = 손절선. 식대로면 2.0배 안팎).
- **과거 참고**(2026-09-26 추가): 한 줄 판단 문장 바로 다음에 `과거 참고: 2025-01 이후 이 종목이 '<오늘 판단>'이었던 <N>일, 그 뒤 60거래일 평균 수익률 <X>%, 오른 비율 <Y>%다 (산출)`를 씁니다. 판단 근거 칸 마지막 줄에도 짧게 넣습니다. 숫자는 맨 아래 **과거 판단 성과 표**에서 그대로 옮기고 새로 계산하지 않습니다. 칸이 `없음`이면 `과거 참고: 같은 판단의 과거 표본 없음`, N이 30일 미만이면 끝에 `(표본 적음)`. 표가 판단과 반대 방향이어도 라벨·구간은 규칙대로 두고, 해석은 (의견) 한 문장까지만 씁니다.
- 구간의 숫자마다 괄호로 식을 적습니다. 예: `262,000원(20일선 262,250원 → 500원 단위 내림)`.
- 반올림 단위 = 종가 기준 **KRX 호가 단위**: 2,000원 미만 1원 · 5,000원 미만 5원 · 2만 원 미만 10원 · 5만 원 미만 50원 · 20만 원 미만 100원 · 50만 원 미만 500원 · 50만 원 이상 1,000원. 매수 구간 하단·차익 실현 하단·손절선은 내림, 매수 구간 상단·차익 실현 상단은 올림.
