01 / 구조architecture

하루 여섯 번, 사람 없이 돕니다Six runs a day, no human in the loop

담당은 원출처에서 값을 모으고, 검증은 담당이 쓴 숫자를 믿지 않고 원출처에서 다시 받아 다시 계산합니다. 규칙은 버전 관리되는 프롬프트 파일에 있고, 배포한 뒤 저장본을 원본과 글자 단위로 대조합니다.Desks collect values from the source. The verifier doesn't trust them — it refetches and recomputes. Rules live in versioned prompt files, and the deployed prompt is diffed character-by-character against source.

02 / eval

검증 담당은 오류를 얼마나 잡나How much does the verifier actually catch?

결함을 심은 시험 행으로 검증 담당을 채점하고, 놓친 유형만 겨냥해 규칙을 고친 뒤 다시 쟀습니다. 같은 세트에서 66.7% → 91.7%, 규칙을 고친 뒤 새로 만든 처음 보는 행(holdout)에서 33.3% → 66.7%였고, 정상 행 오탐은 0건을 유지했습니다.The verifier was graded on rows with planted defects, the rules were patched only for the misses, and it was graded again. Same set: 66.7% → 91.7%. Fresh holdout rows written after the patch: 33.3% → 66.7%. False alarms on clean rows stayed at zero.

판단 규칙은 수익 신호가 아니라 위험 관리 도구였다The trading rule was a risk control, not a return signal

매일의 판단 뒤 60일을 겹쳐 세면 '비중 축소' 뒤가 가장 좋아 규칙이 거꾸로 작동하는 것처럼 보였습니다. 겹치지 않는 창으로 다시 뽑자 차이는 신뢰구간 안에서 사라졌습니다. 규칙을 비중으로 쓰면 수익은 11개 자산에서 줄었지만 낙폭은 11개 자산에서 얕아졌습니다.Counting overlapping 60-day windows made 'REDUCE' look like the best entry — as if the rule worked backwards. With non-overlapping windows the gap vanished inside the confidence intervals. Used as position sizing, the rule lowered return on 11 assets but reduced max drawdown on 11.
